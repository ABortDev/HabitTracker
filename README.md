Habit Tracker

Вебзастосунок для формування корисних звичок, контролю їх виконання та аналізу особистого прогресу.

## 1. Призначення системи

Habit Tracker допомагає користувачам створювати та відстежувати повсякденні звички. Система зберігає історію виконання, нараховує бали, формує статистику та повідомляє користувача про важливі події.

Застосунок також містить систему досягнень, профіль користувача, повідомлення та засоби взаємодії з модератором.

## 2. Основний функціонал

- реєстрація та авторизація користувачів;
- створення, редагування та видалення звичок;
- визначення періодичності, складності, категорії та цільового значення звички;
- налаштування нагадувань;
- позначення виконання звичок;
- перегляд історії виконання;
- перегляд календаря звичок;
- перегляд статистики та особистого прогресу;
- нарахування балів за виконання завдань;
- отримання досягнень;
- перегляд і редагування профілю користувача;
- отримання та перегляд повідомлень;
- позначення повідомлень як прочитаних;
- надсилання повідомлень модератору;
- перегляд модератором звернень користувачів та надсилання відповідей;
- блокування користувачів адміністратором.

## 3. Ролі користувачів

### Користувач

Користувач може:

- зареєструватися та увійти до системи;
- керувати власними звичками;
- позначати виконання звичок;
- переглядати календар, статистику та досягнення;
- редагувати власний профіль;
- переглядати повідомлення;
- звертатися до модератора.

### Модератор

Модератор може:

- переглядати звернення користувачів;
- переглядати окремі діалоги;
- відповідати на повідомлення користувачів;
- отримувати сповіщення про нові звернення.

### Адміністратор

Адміністратор може керувати користувачами системи, зокрема переглядати їхні дані та блокувати облікові записи у разі потреби.

## 4. Використані технології

- .NET 9;
- ASP.NET Core MVC;
- Entity Framework Core;
- ASP.NET Core Identity;
- PostgreSQL;
- Npgsql Entity Framework Core Provider;
- Razor Views;
- HTML, CSS та JavaScript;
- Visual Studio.

## 5. Структура проєкту

Основний проєкт розташований у каталозі `Habit_Tracker_Project`.

- `Controllers` — контролери для авторизації, звичок, статистики, досягнень, повідомлень і чату;
- `Models` — моделі предметної області та даних користувача;
- `Data` — контекст бази даних Entity Framework Core;
- `Views` — Razor-представлення вебсторінок;
- `Migrations` — міграції структури бази даних;
- `Filters` — фільтри доступу до функціоналу застосунку;
- `Program.cs` — конфігурація сервісів і конвеєра обробки запитів;
- `appsettings.json` — конфігураційні параметри застосунку та рядок підключення до бази даних.

## 6. Вимоги для запуску

Перед запуском необхідно встановити:

- .NET SDK 9.0 або новішої сумісної версії;
- PostgreSQL або доступ до віддаленої PostgreSQL-бази даних;
- Visual Studio 2022/2026 або інше середовище, що підтримує .NET 9.

## 7. Налаштування бази даних

1. Створіть PostgreSQL-базу даних.
2. Вкажіть рядок підключення у файлі `Habit_Tracker_Project/appsettings.json` або за допомогою Secret Manager.
3. Не зберігайте реальні паролі та інші секрети у відкритому репозиторії.

Приклад структури налаштування:

```json
{
  "ConnectionStrings": {
	"DefaultConnection": "Host=localhost;Port=5432;Database=habit_tracker;Username=postgres;Password=your_password"
  }
}
```

## 8. Запуск проєкту

Відкрийте термінал у корені репозиторію та виконайте:

```powershell
dotnet restore
dotnet build
```

За потреби застосуйте міграції бази даних:

```powershell
dotnet ef database update --project Habit_Tracker_Project
```

Запустіть застосунок командою:

```powershell
dotnet run --project Habit_Tracker_Project
```

Після запуску відкрийте адресу, яку буде виведено в терміналі, наприклад:

```text
https://localhost:xxxx
```

Також проєкт можна запустити з Visual Studio за допомогою кнопки запуску або профілю HTTPS.

## 9. Безпека

Застосунок використовує ASP.NET Core Identity для реєстрації, автентифікації та авторизації користувачів. Доступ до функцій обмежується за допомогою атрибутів авторизації та ролей.

Під час розгортання необхідно:

- зберігати рядок підключення поза репозиторієм;
- використовувати змінні середовища або Secret Manager;
- не публікувати паролі та ключі доступу;
- використовувати HTTPS.
